How the code works

  • Count each task, then put all negative frequencies in a heap.
  • At each time, release tasks whose cooldown has finished.
  • Run the available task with the highest remaining frequency.
  • If no task is ready, jump to the next release time; those skipped slots are idle.

Why the waiting queue is FIFO

Every task run at time t gets the same cooldown length, so tasks enter the queue in release-time order. The queue's front is therefore the next task that can return to the heap.

Time: O(T log K) · Space: O(K)

T = total intervals in the schedule; K = distinct task types.
